01

Overview

This lab reproduces a full 5G Standalone core — AMF, SMF, UPF, AUSF, UDM, UDR, PCF, NSSF, NRF — using free5GC, plus a simulated radio access network (gNB + UE) using UERANSIM. Everything runs as Kubernetes pods on a single-worker kind cluster on this host, deployed from the towards5gs-helm Helm charts (vendored and patched locally — see §8). The UE registers, establishes a PDU session, and pings the public internet through the UPF end to end.

08

Issues hit and resolved

towards5gs-helm bundles a 2023-era (v3.2.1) free5GC build. Its UPF requires gtp5g 0.8.1–0.8.x, which doesn't compile against this host's kernel without patching two removed/changed kernel APIs — current gtp5g does compile cleanly, so every NF was bumped to the current official free5gc/<nf>:v4.2.3 image instead (a mixed v3.2.1/v4.2.3 stack turned out not to interoperate: SBI response schemas, config validation, and even the subscriber data model all moved between those releases). Each fix below was applied to the vendored charts in charts/towards5gs-helm/.

✓

gtp5g's own latest release tag is stale for this kernel

Even gtp5g's own latest release tag (v0.10.2) still references a kernel struct field (flowi4_tos) this host's kernel renamed to flowi4_dscp. That fix landed on gtp5g's master branch but hasn't been cut into a tag yet, so 01-install-gtp5g.sh tracks master instead of pinning a tag — a reproducibility tradeoff, documented in the script, worth revisiting once a newer tag ships.

✓

Image layout & static-IP rollouts (every NF)

The old image's WORKDIR was /free5gc/<nf> with the binary at /free5gc/<nf>/<nf>; the current image is flat (WORKDIR /free5gc, binary at /free5gc/<nf>) — fixed by switching every NF's command/args/TLS-cert paths to absolute. AMF/SMF/UPF also have static ipvlan N-interface IPs, so Kubernetes' default RollingUpdate deadlocked on any change (new pod can't get the IP while the old one holds it) — fixed with strategy: Recreate.

✓

Config schema drift (UDR, AMF, WebUI)

UDR needed dbConnectorType: mongodb added and info.version bumped 1.0.2→1.1.0 (validated strictly, not just descriptive). AMF needed a t3555 retransmission-timer block added. WebUI needed nrfUri/webServer/billingServer added and info.version bumped 1.0.1→1.0.3 — all newly-required fields the old image's config never had.

✓

Subscriber auth data schema (the deepest issue)

Current UDM/UDR use the 3GPP TS 29.504-shaped AuthenticationSubscription: flat encPermanentKey/encOpcKey hex strings and a structured sequenceNumber ({sqn, sqnScheme}) — not the old nested milenage/opc/permanentKey objects or a bare sequenceNumber string. The bundled free5gc-dbpython image still writes the old shape (it can't be rebuilt here), so 04-deploy-ueransim.sh now runs a MongoDB migration right after provisioning to fix it up in place, every time.

i

Operational gotcha: NRF's registry is in-memory

NRF here doesn't persist to Mongo (db.enabled: false). Any time its pod restarts, every other NF's registration silently vanishes until that NF also restarts and re-registers — symptoms look unrelated (AMF can not select an AUSF by NRF, UDM discovery failed, PFCP association mismatches). After changing values and re-running 03-deploy-free5gc.sh, if you see NF-discovery errors, restart every core NF pod once: kubectl -n core delete pod -l 'nf in (amf,ausf,smf,upf,udm,udr,pcf,nssf,webui)'.

09

Operations

Ordered setup scripts in lab/scripts/. All except 00/01 run without sudo once your shell has active docker group membership.

  1. 00-install-docker.shInstalls Docker, adds your user to the docker group. Needs sudo — run yourself, then start a new shell.
  2. 01-install-gtp5g.shBuilds & loads the gtp5g kernel module (from its master branch, see §8) the UPF needs for GTP-U. Needs sudo — run yourself.
  3. 02-create-kind-cluster.shCreates the corelab kind cluster, installs CNI plugin binaries + Multus.
  4. 03-deploy-free5gc.shDetects the docker bridge subnet, generates network overrides, deploys all core NFs via Helm.
  5. 04-deploy-ueransim.shProvisions the test subscriber, migrates its auth data to the current UDM/UDR schema (see §8), then deploys the simulated gNB + UE and checks for PDU session establishment.
  6. 05-teardown.shDeletes the whole kind cluster.
  7. 06-wireshark-live.sh [node...] | --all-kindStreams a live capture from one or more kind/docker nodes straight into a local Wireshark window (multi-node capture, one merged session).
  8. 07-capture-to-file.sh [node...] | --all-kindSame, but writes a merged .pcap to lab/cluster/ for later analysis.
